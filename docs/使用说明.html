CampusAutoLoginWeb
校园网自动登录守护

连着校园 Wi-Fi、却上不了外网的时候，自动把网页认证做完。 平时完全静默：没有窗口、没有任务栏图标，只在真的需要认证时才动一次。

入口 run-autologin-web.cmd 静默拉起 start-hidden.vbs 浏览器 Edge / CDP 免打扰 00:00 – 06:30 单实例 lock + pid 校验
是什么 怎么判断 三种运行状态 部署 配置 日志 文件清单 排错 边界

01它解决的问题

校园网是「先认证、后上网」的：网线插着、Wi-Fi 连着，但只要那条线路的认证会话不在了，所有报文都会被上游丢掉，浏览器也不会自动弹认证页。

现象

能连网，不能上网

默认网关 ping 得通、认证门户打得开，唯独公网全超时。系统右下角显示「已连接，但无 Internet」。

原因

认证会话掉了

上游只放行已认证会话的转发。会话被清掉后地址不变、状态仍是已连接，报文却出不去。

本工具

把认证自动做完

定时探外网，一旦发现「在校园网 + 外网不通」，就拉起浏览器走完认证，再用探针确认结果。

02它怎么判断（四层，逐层短路）

每一层都先判定再动作，能不动作就不动作，避免无意义地开浏览器、也避免把服务端刷出风控。

1
探外网：一个 204 探针

请求 generate_204 这类地址，返回 204/200 就算在线。在线就什么都不做，直接睡（默认 3600 秒后再看）。不用 ping 判断，因为上游只封转发，ICMP 常常还是通的，会骗人。

↓ 外网不通
2
确认自己在校园网里

三条任一成立即可：默认网关等于配置里的校园网关、WAN 网关 10.100.0.1 可达、认证门户 TCP 可达。不在校园网（比如连着手机热点）就不动手。

↓ 在校园网
3
走 AC 重定向，拿到「真正可用」的登录页

这一步是成败关键：直接打开门户首页或直连 login.jsp，提交时会缺 wlanuserip / wlanacname / nasip / mac 这几个由接入设备算好的密文参数，服务端会回「Web认证接入设备不存在」。所以必须先访问一个会触发 302 的地址，让 AC 把浏览器带到带参数的登录页。

↓ 拿到带参登录页
4
填表、选出口、点登录，然后用探针验收

通过 CDP 往 Edge 里注入填充脚本：写学号密码、选中出口（校园网 / 中国移动 / 中国联通）、触发页面自己的 doauthen()。之后只看探针结果，页面说什么都不算数。

为什么不看返回话术

服务端的提示不可靠

同一句「登录成功」可能出现在会话早已失效的壳页上；反过来真成功时也可能只返回一段跳转脚本。唯一的硬判据是「公网探针从失败变成 204」。

03三种运行状态

双击、开机、重复双击，表现各不相同，但共同点是：不会留下窗口，也不会堆出多份进程。

触发方式它会做什么窗口
双击
run-autologin-web.cmd		 打印 python 路径、配置、日志位置、免打扰时段 → 注册开机自启 → 用 wscript 拉起无窗口实例 → 校验锁里的 pid 真活着 → 显示 [ok] running in background 后自己退出 约 7 秒后自动关闭
开机自启 Startup 项调用 wscript.exe start-hidden.vbs，vbs 以窗口样式 0 执行 run-autologin-web.cmd hidden，进入守护循环 全程无窗口
已在跑时再双击 读锁里的 pid，用 tasklist 校验进程名确实是 python，判定为重复启动，提示 already running 约 3 秒后自动关闭
带参数调用 --diagnose 打印六行判断依据；--once 手动跑一轮并输出每个候选页的结果；--force 忽略免打扰窗口 有窗口，不干扰后台那份
两个容易误会的点

1) 窗口关了不等于脚本停了

首次启动拉起的是独立的后台实例，前台那个 cmd 只是启动器。关掉它、甚至从任务管理器里关掉启动器，后台照样在跑。真要确认，看任务管理器里的 python.exe，或者看日志有没有新行。

2) 后台模式是显式参数

vbs 传 hidden 进去，cmd 才会进入守护循环；不带参数走的是「启动一次然后退出」。这样就不会出现后台又拉起后台的递归。

04部署（三步，两分钟）

1
解压到固定位置

例如 D:\CampusAutoLoginWeb。解压完就不要再移动 —— 开机自启里写的是绝对路径，挪了地方要么重新跑一次安装，要么双击一次启动器（它会自动刷新自启路径）。

2
双击 install-autologin-web.cmd

写自启（指向 start-hidden.vbs）→ 尝试注册登录时触发的计划任务（非管理员会跳过，不影响使用）→ 立刻后台拉起 → 校验锁里的 pid，打印结果。

3
验证判断逻辑

双击启动器看它是不是报 already running，或直接跑 run-autologin-web.cmd --diagnose，会输出：账号、默认网关、在线与否、在不在校园网、是否处于免打扰窗口、该不该动作。

:: 只看判断，不动手
run-autologin-web.cmd --diagnose

:: 手动跑一轮，会打开浏览器并打印每个候选页的结果
run-autologin-web.cmd --once

:: 忽略免打扰窗口强行登录（服务端多半还是会拒）
run-autologin-web.cmd --force

:: 彻底卸载：删自启 + 杀监督窗口 + 杀 python + 清锁
uninstall-autologin-web.cmd

05配置项（autologin-web.json）

改完保存即可，下一轮循环生效，不用重启。JSON 里不要加注释。

键默认值说明
user—学号 / 上网账号
password—密码，初始密码通常是身份证后 6 位
portalhttp://172.172.255.20/认证门户根地址
ac10.100.0.235重定向器地址，用来触发带参跳转
net校园网出口名：校园网 / 中国移动 / 中国联通
skip_start00:00免打扰窗口开始
skip_end06:30免打扰窗口结束
window_loginfalsefalse 窗口内一次睡到结束；true 窗口内也尝试登录
online_interval3600已经能上网时，隔多少秒再看一眼
debug_port9333Edge 调试端口，被占用时换一个
headlessfalsetrue 不开可见窗口，调试期建议保持 false
login_wait25点完登录后等多久用探针验收（秒）
免打扰窗口为什么默认开着

服务端在 00:02 – 06:29 这一段会对该账号拒绝认证，返回「不在认证时段内」。这段时间反复提交毫无意义，还会把自己的账号刷进风控，所以默认整段睡过去，到 06:30 之后再看。确认服务端放通时刻后，把 skip_end 调准即可。

06看日志：一行一个事件

autologin-web.log 是单行 JSON，8MB 自动轮转。别用 PowerShell 5 的 Get-Content 直接看，它会按本地代码页解码把中文显示成乱码；用记事本、VS Code，或 python 读。

event含义要不要管
start守护启动。note 里带间隔、免打扰窗口、窗口内是否登录正常
skip撞到免打扰窗口，一次睡到 skip_end，中途不探测正常
window窗口内仍尝试登录（只在 window_login=true 时出现）正常
loginok:true 探针确认已经能上网成功
loginok:false note 里逐个候选页写了失败原因要看 note
abort已有实例在跑，本次退出（单实例保护）正常
once--once 的单次运行结果调试用

08排错对照

症状

只看到浏览器打开，表单没填

多半是当前页面不是带参数的真正登录页。看日志 note 里哪个候选页「无登录表单」，以及有没有走到兜底 HTTP 登录。首次真实断网时，AC 的 302 才会把 wlanuserip 这组参数带上。

症状

提示「Web认证接入设备不存在」

服务器找不到该由哪台接入设备处理这次认证 —— 因为会话里没有 AC 带过来的密文参数。不是密码错，也不是时段问题。必须让 AC 的 302 先把浏览器带到认证页。

症状

双击后窗口一闪就没了

这是设计行为：启动器确认后台实例起来后自动关窗。判断是否真在跑 —— 任务管理器看 python.exe，或看日志有没有新行。

症状

日志中文乱码

文件本身是 UTF-8。PowerShell 5 的 Get-Content 按系统代码页读会乱，换编辑器或 python -c "print(open('autologin-web.log',encoding='utf-8').read())"。

症状

换了文件夹就不自启了

自启里是绝对路径。在新目录双击一次 run-autologin-web.cmd，它会重写自启；或者重跑安装脚本。旧目录那份记得删掉，免得两份抢着跑。

症状

杀不掉 / 杀了又起来

守护 cmd 会在 python 异常退出后 15 秒重启它。所以要用卸载脚本：它先杀监督 cmd，再杀 python。手动处理就 taskkill /T 连父进程一起杀。

09边界与注意

做不到

时段封禁期内的认证

服务端在窗口期直接拒绝认证。客户端再怎么提交都只会拿到拒绝话术。脚本能做的是「窗口一结束立刻登上」，而不是「在窗口里绕过」。

设计取舍

不伪造任何身份

用的是配置里的真实账号口令，走的是页面自己的登录流程，不改 MAC、不改 IP、不碰服务端接口。本质是把「人工点一次」变成「自动点一次」。

运行成本

在线时几乎不耗资源

在线状态下一次探针 + 一次长睡眠（默认 1 小时）。只有真正需要认证时才启动 Edge，登录完成或超时后按配置决定是否关闭浏览器。

兼容性

不需要装任何库

只用 Python 3 标准库；浏览器用系统已装的 Edge（找不到时回退 Chrome）。CDP 客户端是自带实现，因此不会被 pip 源、内网代理卡住。

这一版改了什么

首次启动自动关窗 + 全程静默

  • 启动器确认后台实例起来后自动退出关窗，不再需要手动关窗口
  • 后台模式改为显式 hidden 参数，由 vbs 传入，杜绝递归启动
  • 开机自启只走 start-hidden.vbs，窗口样式 0，无任务栏图标
  • 重复双击提示 already running 并自动关窗，锁里的废 pid 会被自动接管
  • 安装器增加 pid 校验；卸载器改为先杀监督 cmd 再杀 python
  • 所有 .cmd / .vbs 统一为纯 ASCII + CRLF，规避中文注释导致的解析错误
