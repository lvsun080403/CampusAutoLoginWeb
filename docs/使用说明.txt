CampusAutoLoginWeb 使用说明
==================================================

一、这个包干什么
--------------------------------------------------
在连着校园网、但上不了外网的时候，自动打开浏览器把上网认证做完。
判断顺序：
  1. 先探外网（204 探针）。能通就什么都不做，直接睡（默认 3600 秒后再看）。
  2. 探不到外网，再判断自己在不在校园网（默认网关 == 192.168.1.1，
     或者 WAN 网关 10.100.0.1 可达，或者认证门户 TCP 可达）。
  3. 在校园网但没网 → 拉起 Edge，先走 AC 重定向拿到带密文参数的登录页，
     填学号密码、选出口、点登录，最后用探针确认真的通了才记为成功。
  4. 00:00 - 06:30 默认整段不动作（服务端这个时段拒绝登录，脚本白跑）。
     这段按配置一次睡到 06:30，中途不探测、不开浏览器。

二、第一次部署（三步）
--------------------------------------------------
1. 把整个 CampusAutoLoginWeb 文件夹放到一个固定位置，例如
   D:\CampusAutoLoginWeb
   放好之后不要再移动。移动了要重新跑一次安装，否则开机自启还指老路径。

2. 双击 install-autologin-web.cmd
   它会做四件事：写开机自启（指向 start-hidden.vbs）、尝试注册计划任务
   （非管理员会跳过）、立刻在后台拉起、然后检查进程是否真的起来了。
   窗口会显示最后的 python pid，看一眼心里有数。

3. 想看它判断得对不对，用这条（有窗口，不影响后台那份）：
   run-autologin-web.cmd --diagnose
   会打印：账号 / 默认网关 / 在线与否 / 在不在校园网 / 是否窗口内 / 该不该动作。

三、之后的表现
--------------------------------------------------
情形一：开机自动跑
  自启项是 wscript 调 start-hidden.vbs，窗口样式 0 —— 没有任何窗口、
  任务栏也看不到，只在任务管理器里有一个 python.exe。

情形二：自己双击 run-autologin-web.cmd
  会看到一个小窗口打印 python 路径、配置、日志位置，然后：
    - 如果已经在后台跑：显示 already running，约 3 秒后窗口自己关掉；
    - 如果没在跑：显示 starting in background，拉起无窗口实例，
      再显示 ok，约 6 秒后窗口自己关掉。
  两种情况下都不会留下窗口，运行全部在后台。

情形三：重复双击、重复开机
  靠 autologin-web.lock 里的 pid 做单实例判定，只会有一份在跑。
  被强杀过留下废锁也没关系，新实例会检测到进程不存在并接管。

四、改配置（autologin-web.json）
--------------------------------------------------
user             学号
password         密码
portal           认证门户地址，默认 http://172.172.255.20/
ac               重定向器地址，默认 10.100.0.235
net              出口名：校园网 / 中国移动 / 中国联通
skip_start       免打扰窗口开始，默认 00:00
skip_end         免打扰窗口结束，默认 06:30
window_login     true = 窗口内也尝试登录；false = 窗口内一次睡过去
online_interval  已经能上网时，隔多少秒再看一眼，默认 3600
debug_port       Edge 调试端口，默认 9333
headless         true = 不开可见窗口（调试时用 false 好观察）
login_wait       点完登录后等多久探针，默认 25 秒

五、看日志
--------------------------------------------------
autologin-web.log 是单行 JSON，一行一个事件。关键看 event 和 ok：
  start   守护启动，note 里有间隔、窗口、窗口内是否登录
  skip    撞到免打扰窗口，睡到 skip_end
  login   ok=true 表示探针确认已经能上网；ok=false 时 note 里写着
          每个候选页为什么失败（无登录表单 / 打不开 / 兜底 HTTP 也没通）
  abort   已有实例在跑，本次退出
  once    --once 单次运行的结果
supervisor.log 只在进程异常退出并准备重启时写。

六、做不到什么
--------------------------------------------------
00:02 到 06:29 之间，服务端直接拒绝认证，返回“不在认证时段内”。
这段时间脚本会一直重试到 06:30 之后，但不保证在这之前能把网弄通。
这不是脚本的问题，是账号级时段策略，客户端绕不过去。

七、停止与卸载
--------------------------------------------------
双击 uninstall-autologin-web.cmd：
  删开机自启 → 删计划任务 → 杀掉监督窗口 → 杀掉 python → 关掉 9333 上的
  调试浏览器 → 删锁文件。跑完就彻底不启动了。
临时停一下，也可以在任务管理器里结束 python.exe（自启项还在，下次开机会再起）。

八、排错
--------------------------------------------------
只看到浏览器打开但没填进去
  多半是登录页不是带参数的真正登录页。看日志 note 里哪个候选页“无登录表单”，
  以及最后是不是走到了兜底 HTTP 登录。

提示 Web认证接入设备不存在
  说明提交时缺少 AC 带过来的密文参数（wlanuserip/wlanacname/nasip/mac）。
  必须让 AC 的 302 先把浏览器带到认证页，脚本里第一个候选就是干这个的。

双击后窗口一闪就没了
  这是正常的（首次启动会在 6 秒左右自动关窗）。确认是否真在跑：
  任务管理器看 python.exe，或者看 autologin-web.log 有没有新行。

日志里中文是乱码
  日志本身是 UTF-8。Windows PowerShell 5 用 Get-Content 按本地代码页读会乱，
  用记事本、VS Code 或 python 读就正常。

九、文件清单
--------------------------------------------------
autologin-web.py            主程序（判断 + 调度 + 登录）
cdp.py                      自写的 Chrome DevTools 客户端，驱动 Edge，无需装库
autologin-web.json          配置
run-autologin-web.cmd       入口：无参=首次启动并转后台；hidden=后台模式；带参=直接跑
start-hidden.vbs            无窗口拉起（开机自启和首次启动都用它）
install-autologin-web.cmd   部署：写自启 + 立即后台启动 + 校验
uninstall-autologin-web.cmd 卸载：清自启 + 杀进程 + 删锁
net_try.py / stu_login.py   兜底 HTTP 登录（浏览器路线失败时用）
使用说明.txt                本文件

十、这一版改了什么
--------------------------------------------------
1. 首次启动完成后窗口自动关闭：双击 run-autologin-web.cmd 打印几行信息，
   拉起后台实例，确认起来后自己退出，不再需要手动关窗口。
2. 开机自启只走 start-hidden.vbs，窗口样式 0，全程无窗口、无任务栏图标。
3. 后台模式改为 run-autologin-web.cmd hidden，由 vbs 显式传入，
   避免“后台再拉起后台”的递归启动。
4. 重复双击有明确提示（already running）并自动关窗，不会堆出多份实例。
5. 安装脚本改为优先用 wscript 启动并校验锁里的 pid 是否真活着；
   卸载脚本增加“先杀监督窗口再杀 python”，否则杀完 python 会被脚本重启。
